## Démarrage

Prérequis : Docker avec Compose, daemon démarré, Python 3 et port 8080 libre.
Depuis `jabfy-deploy`, seul dépôt responsable de l'orchestration :

```sh
python3 scripts/start.py --check  # contrôle des sources et de Compose, sans démarrage
python3 scripts/start.py         # build, démarrage, installation de qwen2.5:1.5b
```

Le lanceur utilise explicitement `compose.local.yml`, construit depuis les sources
locales. Le `docker-compose.yml` historique concerne les images publiées et n'est
pas le point d'entrée de cette V0.0.1. Ne pas démarrer ces deux configurations ensemble.

Simulation fournit son image et son interface ; elle ne démarre ni Core ni Ollama.
Guard reste une bibliothèque Python et Bus un moteur embarqué dans le processus de
simulation, pas deux services réseau autonomes. Deploy assemble et démarre ce runtime.

Le nom de projet Compose `jabfy-simulation` est conservé uniquement pour réutiliser
les anciens conteneurs et le volume de modèles. Les données restent à leur emplacement
initial dans `../jabfy-simulation/data` : aucun déplacement ni effacement nécessaire.
Si des ports étaient personnalisés via l'ancien `.env` de Simulation, reporter ces
valeurs dans `jabfy-deploy/.env` (ignoré par Git) avant de relancer.

Le premier lancement télécharge images, dépendances et modèle : prévoir Internet,
de l’espace disque et plusieurs minutes. L’inférence reste locale. La qualité du petit
modèle n’est pas garantie ; ses propositions restent vérifiées et ne s’exécutent jamais seules.

Sans téléchargement de modèle : `python3 scripts/start.py --no-ai`.
Autre modèle : `python3 scripts/start.py --model NOM_DU_MODELE`.
Ports occupés : `SIM_PORT=8082 MQTT_PORT=1884 python3 scripts/start.py --no-ai`.

Ouvrir http://127.0.0.1:8080. Modifier et enregistrer la maison, sélectionner un appareil
pour le commander. Dans l’onglet IA : actualiser les modèles, demander une proposition,
puis cliquer explicitement sur Appliquer. Les contrôles manuels fonctionnent sans modèle.

## Sécurité et limites

- Un seul Bus, embarqué dans le simulateur ; pas de second service Bus à démarrer.
- Commandes manuelles, propositions IA appliquées et automatismes passent par Guard.
- Catalogue, règles, identité et adresses sont construits côté serveur pour les seuls
  appareils virtuels de cette maison ; pas à partir d’une autorité déclarée par le navigateur.
- Les actions sensibles exigent contexte simulation et règle explicite. La restriction
  par défaut sur matériel réel reste en place. Objets RGB bornés pris en charge.
- Limite de 60 commandes par appareil, par source et par minute. Compteurs en mémoire,
  réinitialisés au redémarrage/changement de maison ; pas un quota durable.
- Approbation liée à la commande exacte, à usage unique pendant l’envoi synchrone.
  Écriture d’audit avant admission ; erreur d’audit = aucun envoi.
- `JABFY_GUARD_MODE=restricted python3 scripts/start.py --no-ai` bloque les commandes.
- Maison dans `../jabfy-simulation/data/home.json`, audit dans `../jabfy-simulation/data/home.audit.jsonl`, modèles dans le volume
  Docker `ollama-models`. Les états instantanés des appareils ne survivent pas au redémarrage.
- Accès local uniquement, sans authentification multi-utilisateur : ne pas exposer sur Internet.
- Pas de transaction atomique multi-appareils. Des erreurs réseau restent possibles après autorisation.
- Les images amont et dépendances ne sont pas toutes figées : ce n’est pas une release de production reproductible à l’octet.

## Arrêt et diagnostic

```sh
docker compose -f compose.local.yml ps
docker compose -f compose.local.yml logs --tail=100 core jabfy-sim ollama
docker compose -f compose.local.yml down # conserve les données ; ne pas ajouter -v
python3 scripts/start.py --no-ai
docker compose -f compose.local.yml exec ollama ollama list
```

Un Core sain ne garantit pas la présence d’un modèle. Une IA indisponible n’empêche
pas le pilotage manuel. Un audit corrompu bloque le démarrage : conserver le fichier
pour diagnostic, ne pas le supprimer pour contourner le contrôle.

## Tests communs sans Docker ni modèle

Depuis le dossier parent des dépôts :

```sh
python3 -m venv .venv-v001
.venv-v001/bin/python -m pip install -e './jabfy-guard[dev]' -e './jabfy-bus[all]' -e './jabfy-core[dev]' -e './jabfy-simulation[dev]'
(cd jabfy-guard && ../.venv-v001/bin/python -m pytest -q)
(cd jabfy-bus && ../.venv-v001/bin/python -m unittest discover -s tests -q)
(cd jabfy-core && ../.venv-v001/bin/python -m pytest -q)
(cd jabfy-simulation && ../.venv-v001/bin/python -m pytest -q)
(cd jabfy-deploy && ../.venv-v001/bin/python -m pytest -q)
```

`tests/test_stack_integration.py` teste les vrais contrats et moteurs avec modèle et
transports simulés. Ce fichier est explicitement ignoré sans Core installé : installer
les quatre paquets pour valider toute la livraison.
