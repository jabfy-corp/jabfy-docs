# Suivi du projet

## Organisation

- Chaque **action** décidée en RDV devient une **issue** GitHub, dans le repo concerné.
- Chaque **jalon** est une **milestone** GitHub, voir [Roadmap et jalons](../projet/roadmap.md).
- Issues et milestones sont regroupées dans le **GitHub Project** de l'organisation.
- Le tableau d'actions d'un compte-rendu pointe vers les issues (`jabfy-core#12`) : l'avancement se suit dans GitHub, sans recopier les statuts à la main.

## Comptes-rendus

Un fichier par RDV, nommé `AAAA-MM-JJ.md`, créé à partir du [modèle](modele-rdv.md), puis ajouté dans `SUMMARY.md` et ci-dessous.

| Date | Compte-rendu | Points clés |
|---|---|---|
| 29/10/2026 | [RDV de suivi](2026-10-29.md) (préparé) | Doc, veille, architecture et premières mesures livrées ; emplacement du bus et API de Core à trancher |
| 16/10/2026 | [RDV de suivi](2026-10-16.md) | Choix des objectifs 1, 2, A et D ; grandes étapes et suivi à préparer |

## Avant chaque RDV

1. Copier le [modèle](modele-rdv.md) sous la date du RDV.
2. Remplir la revue de l'avancement : actions du RDV précédent, ce qui a été livré, avec les liens vers les pages ou les PR.
3. Lister les points à trancher, pour que la réunion serve à décider.
4. Pendant le RDV : présents, décisions, actions avec leurs acteurs. Juste après : une issue par action, et son numéro dans le tableau.
